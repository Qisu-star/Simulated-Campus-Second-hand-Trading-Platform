# ADR：课程搜索的职责与数据访问边界

> 编号：ADR-002  
> 状态：提议中，未实施  
> 日期：2026-07-12  
> 关联 Spec：[003：课程关键词搜索](../../specs/003-course-keyword-search.md)

## 背景

课程目录计划支持可选关键词搜索。该能力既改变 HTTP 输入与错误语义，也新增查询规则和用户输入驱动的数据访问。如果不先固定职责，后续实现容易在 Controller 中拼接 SQL、在前端过滤全量数据，或让 Service、数据库和 Contract 分别采用不同的空白、大小写、通配符及排序语义。

本 ADR 只决定实现长期遵守的技术边界。关键词含义、状态码和可观察结果仍以关联 Spec 与未来正式 OpenAPI 为准。

## 决策

- **API**：搜索继续使用课程集合资源 `GET /api/courses` 的可选 `keyword` Query，不新增 `/searchCourses` 等动词式路径。正式开发时，先在 OpenAPI 中声明参数、成功与失败响应、公开访问和 Spec 追踪。
- **Controller**：负责读取单值 Query，拒绝重复或非字符串输入，按 Contract 完成“去除首尾空白 → 校验 Unicode 字符数”的同一归一化流程，再调用 Service 并把已知错误转换为稳定 HTTP 响应；不得包含匹配规则或 SQL。
- **Service**：负责缺失或归一化后为空时返回全部课程，以及搜索字段、ASCII 大小写、空结果和确定性排序等业务规则；它只依赖可注入的数据访问接口，不依赖 Midway 请求对象。
- **Repository**：负责 SQLite 查询与行到 `Course` 的映射。所有外部输入都通过参数绑定；使用 `LIKE` 时先转义 `%`、`_` 和 `\` 并显式声明转义字符，只承诺 SQLite 可稳定提供的 ASCII 大小写折叠，最后固定 `ORDER BY id ASC`。
- **依赖与演进**：继续使用平台提供的 `node:sqlite`，不为单个包含查询引入 ORM、缓存或搜索引擎。本次不改变表结构；只有数据规模和查询证据证明需要时，才另行决定索引、FTS、分页或异步搜索。
- **质量**：Service Test 验证搜索规则，Repository Test 验证参数化与通配符，API / Contract Test 验证状态码、Schema 和 requestId。日志记录 requestId、是否提供关键词、归一化后长度、命中数量和耗时，不记录原始关键词、SQL 或敏感信息。

## 原因

- Query 表达对课程集合的筛选，不会创造一种新的资源身份；旧调用方省略参数时仍可沿用原列表语义。
- 将 HTTP、业务和存储职责分开后，可以用替身数据访问验证 Service 规则，也可以独立验证 SQLite 查询与异常映射。
- 参数绑定阻止输入变成 SQL 结构；额外转义通配符可以满足 Spec 中“特殊字符按字面匹配”的业务语义。
- 稳定排序和响应 Schema 让前端、测试与 Agent 在有结果和无结果时使用同一套解释方式。
- 复用 `node:sqlite` 符合课程仓库的最小依赖原则；当前没有证据证明需要更重的数据方案。

## 后果

- 若该提议被采纳，现有 `CourseService` 直接访问 SQLite 的最小结构需要演进为可注入 Repository；Controller、Service 和 Repository 的测试边界也要随之补齐。
- 不携带 `keyword` 的课程列表必须继续满足已有目录 Spec，搜索实现不能改变默认字段、空列表或 `id` 升序语义。
- 包含匹配在数据增长后可能产生全表扫描；应先通过数据量、延迟和查询计划观察，再用新的 ADR 决定索引或全文搜索，而不是预先引入复杂度。
- HTTP 行为只有在正式 Spec、OpenAPI、实现和验证证据同步后才算交付；本 ADR 处于提议状态，不能作为已完成的证明。

## 不采用

- **在 Controller 中直接拼接或执行 SQL**：混合协议、业务与存储职责，难以独立测试，也会扩大注入和错误泄露风险。
- **由前端下载全部课程后过滤**：让不同客户端重复业务规则，无法形成统一输入、空结果和错误契约，数据增大后传输成本也不可控。
- **新增 `/api/searchCourses` 或 `/api/courses/search` 动作入口**：课程搜索是集合筛选，现有资源 Query 已能表达，不需要重复的调用边界。
- **只做参数绑定而保留 `%`、`_` 的通配符语义**：虽然避免 SQL 注入，但会违反 Spec 的字面匹配规则，产生用户不可预期的扩大结果。
- **立即引入 TypeORM、缓存或外部搜索引擎**：当前场景和规模不足以抵消依赖、迁移、部署与运维成本。
