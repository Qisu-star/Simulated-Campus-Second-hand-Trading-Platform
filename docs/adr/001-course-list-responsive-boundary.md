# ADR：课程列表响应式布局的职责边界

> 编号：ADR-001  
> 状态：已采纳  
> 日期：2026-07-11  
> 关联 Spec：[002：课程列表响应式展示](../../specs/002-course-list-responsive-presentation.md)

## 背景

课程列表需要在手机和桌面视口中采用不同列数，同时保持既有数据来源、页面状态和可访问性。该改动涉及列表容器、单张课程卡片、响应式机制与验证边界，需要用一项稳定决策避免后续实现把布局职责分散到卡片、全局配置或 JavaScript 状态中。

## 决策

- **页面**：现有首页路由与页面壳保持不变，课程区域继续承载既有的请求状态呈现；本 ADR 不迁移现有取数或状态边界。课程列表容器负责网格、间距与响应式列数，单张课程卡片只负责自身内容、语义和交互状态。
- **数据**：课程数据继续通过同源 `/api/*` 和 OpenAPI 契约获取；响应式展示不得改变请求、缓存、错误语义、课程顺序或字段内容，前端组件不得直连数据库。
- **交互**：使用组件范围内的现有 Tailwind 响应式 utility 生成 CSS 媒体查询，不读取 `window.innerWidth`，不为视口宽度新增 React 或全局状态，也不因此扩大 Client Component 边界。静态卡片不伪装成可交互元素；真实链接或控件沿用可见的 `focus-visible` 样式。
- **质量**：实现必须追溯到 Spec 002 的验收标准，并检查手机、桌面、长内容、横向溢出和键盘焦点；交付前运行前端检查和仓库级 `npm run check`。

## 原因

- 列数和卡片间距属于集合布局，由列表容器统一决定可以避免每张卡片互相推断可用宽度。
- 单张卡片保持独立后，可以复用相同的语义、视觉样式和交互反馈，而不复制课程内容结构。
- CSS 媒体查询能在不增加运行时状态、监听器或 hydration 分支的情况下响应视口变化。
- 局部 utility 复用现有断点和设计词汇，影响范围小，也不会让单次页面需求改变全局构建配置。
- 数据和 HTTP 边界保持不变，使本次布局能力能够独立验收，不扩大到后端或 Contract 变更。

## 后果

- 后续调整课程列表列数时，应优先修改列表容器；卡片内部只处理自身内容溢出和交互呈现。
- 若未来多个列表需要共享同一套响应式规则，再基于实际重复抽取共享样式；本次不预先增加全局抽象。
- 2026-07-11 的实现已按本决策落地：列表容器统一负责单列 / 双列切换，卡片内部负责长文本断行，未引入额外视口状态或全局样式变更。
- 后续仍可补充针对长连续文本和四态滚动边界的专门自动化测试，用于降低回归风险。

## 不采用

- **由每张课程卡片决定列数**：单个条目无法可靠掌握集合布局，会混淆卡片与列表职责。
- **修改全局 CSS、Tailwind 或 PostCSS 配置**：单一列表的列数变化不足以证明需要改变全局设计和构建规则。
- **使用 JavaScript 读取视口宽度并保存到局部或全局状态**：会增加监听、同步和 hydration 风险，而 CSS 已能直接表达该需求。
- **为手机和桌面复制两套课程卡片结构**：会造成语义、内容和可访问性行为漂移。
- **新增 API 或让组件直连后端内部 / 数据库**：响应式布局不需要新的数据能力，也不应越过既有同源 API 边界。
