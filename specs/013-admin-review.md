# 013：后台审核

> 状态：草案  
> 关联事项：依赖 003（用户登录与注册）中的管理员角色；004（商家商品管理）中的"待审核"商品状态

## 目标

管理员可在审核界面查看待审核商品，决定是否通过上架，确保平台商品内容合规。

## 用户故事

作为一名管理员，我希望审核用户发布的商品，决定是否允许上架，以便维护平台商品质量。

## 范围

- 系统预置管理员账号（`admin` / `admin123`）
- 管理员导航栏下拉菜单中显示"审核管理"入口
- 审核页面展示所有"待审核"状态的商品列表
- 每条商品展示：名称、价格、数量、描述、展示图、分类、商家
- 管理员可"通过"或"驳回"商品
- 通过后商品状态变为"在售"
- 驳回后商品状态变为"已下架"，商家可在商家界面看到并重新编辑后再次提交

## 非目标

- 多级审核或审核流程审批链
- 审核日志或操作记录
- 商家申诉功能
- 审核通知（如消息推送）
- 审核统计或仪表盘

## 业务规则

- **BR-01**：仅角色为 `admin` 的用户可访问审核接口；非管理员请求返回 403。
- **BR-02**：系统首次启动时预置管理员账号 `admin` / `admin123`，角色为 `admin`。
- **BR-03**：审核页面以列表形式展示所有"待审核"商品，按发布时间倒序排列，支持分页。
- **BR-04**：审核通过后，商品状态变为"在售"，商品出现在浏览页和详情页中。
- **BR-05**：审核驳回后，商品状态变为"已下架"，商家可在商家界面看到该商品并可编辑后重新发布（重新提交后状态恢复为"待审核"）。
- **BR-06**：已通过审核的商品若需再次修改，修改后商品状态保持"在售"不变（无需重新审核）。

## Contract 影响

- 结论：新增
- 理由或影响摘要：新增审核相关接口，仅管理员可访问。
- OpenAPI operation：
  - `GET /api/admin/reviews?page=&pageSize=`（`listPendingReviews`）— 查看待审核商品列表，需管理员
  - `POST /api/admin/reviews/{id}/approve`（`approveItem`）— 审核通过，需管理员
  - `POST /api/admin/reviews/{id}/reject`（`rejectItem`）— 审核驳回，需管理员
- 迁移 / 废弃安排：不适用

## 验收标准

- **AC-01**：给定管理员身份，当请求 `GET /api/admin/reviews` 时，返回所有"待审核"商品，按发布时间倒序排列。
- **AC-02**：给定非管理员用户，当请求 `GET /api/admin/reviews` 时，返回 403。
- **AC-03**：给定管理员审核通过某商品，当请求 `POST /api/admin/reviews/{id}/approve` 时，商品状态变为"在售"，出现在 `GET /api/items` 中。
- **AC-04**：给定管理员审核驳回某商品，当请求 `POST /api/admin/reviews/{id}/reject` 时，商品状态变为"已下架"，不出现在 `GET /api/items` 中。
- **AC-05**：给定被驳回的商品经商家编辑后重新提交，商品状态恢复为"待审核"，再次出现在审核列表中。
- **AC-06**：给定已通过审核的商品，商家编辑后状态保持"在售"不变，无需重新审核。
- **AC-07**：未登录用户请求审核接口返回 401；普通用户请求返回 403。
