# 002：课程列表响应式展示

> 状态：已实现  
> 关联事项：课程前端章节“课程列表响应式样式”示例；[ADR-001：课程列表响应式布局的职责边界](../docs/adr/001-course-list-responsive-boundary.md)

## 目标

学习者可以在手机和桌面视口中清晰浏览课程列表，页面不产生横向溢出，键盘焦点保持可见。

## 用户故事

作为一名学习者，我希望课程列表能适应不同尺寸的屏幕，以便在手机和桌面设备上都能顺畅阅读和操作。

## 范围

- 手机视口中的课程列表使用单列布局。
- 桌面视口中的课程列表使用双列布局。
- 课程标题或简介较长时，内容仍限制在卡片和页面可视区域内。
- 首页已有的“检查 API”链接保留清晰可见的键盘焦点，静态课程卡片不额外进入 Tab 顺序。

## 非目标

- 不改变课程数据、排序、加载方式或加载、成功、空结果、错误四态的业务语义。
- 不新增课程搜索、详情、创建、编辑或删除交互。
- 不改变全局视觉规范、Tailwind 或 PostCSS 配置。
- 不改变任何 HTTP API、请求参数或响应结构。

## 业务规则

- **BR-01**：以 `375 × 812` CSS 像素作为手机验收视口，以 `1280 × 800` CSS 像素作为桌面验收视口。
- **BR-02**：响应式布局只改变课程卡片的排列，不改变课程顺序、字段内容或可见状态语义。
- **BR-03**：课程标题和简介允许在卡片内断行；包含连续无空格字符的长内容不得导致页面出现横向滚动，也不得遮挡相邻卡片。
- **BR-04**：静态课程卡片不进入键盘 Tab 顺序；首页已有的“检查 API”链接获得键盘焦点时必须显示可见焦点。

## Contract 影响

- 结论：无。
- 理由或影响摘要：本能力只调整现有课程列表的页面布局与焦点呈现，不改变 HTTP 请求、响应、排序或错误语义。
- OpenAPI operation：无变更；继续使用 `GET /api/courses`（`listCourses`）。
- 迁移 / 废弃安排：不适用。

## 验收标准

- **AC-01**：给定课程列表非空和 `375 × 812` 视口，当用户打开首页的课程区域时，课程卡片按单列排列，页面不出现横向滚动。
- **AC-02**：给定课程列表非空和 `1280 × 800` 视口，当用户打开首页的课程区域时，课程卡片按双列排列，页面不出现横向滚动。
- **AC-03**：给定课程标题为 80 个连续且无空格的 ASCII 字符 `W`，简介为 500 个连续且无空格的 ASCII 字符 `W`，当用户分别在手机和桌面验收视口查看列表时，文字在卡片内断行，页面和卡片均无横向溢出，相邻内容不重叠。
- **AC-04**：给定首页已显示课程列表，当键盘用户在两个验收视口使用 Tab 键导航时，“检查 API”链接显示清晰的焦点指示，静态课程卡片不会获得焦点。
- **AC-05**：给定课程请求分别处于加载、成功、空结果或错误状态，当用户在两个验收视口查看课程区域时，[Spec 001](./001-course-catalog.md) 定义的对应反馈保持可见，页面不出现横向滚动。
