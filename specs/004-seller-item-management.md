# 004：商家商品管理

> 状态：草案  
> 关联事项：依赖 003（用户登录与注册）中的用户认证；001（商品浏览）和 002（商品详情）中的商品数据结构

## 目标

已登录用户可以管理自己的商品，包括发布新商品、编辑已有商品信息以及下架商品。

## 用户故事

作为一名已登录用户，我希望拥有自己的商家界面，能够发布、编辑和下架商品，以便管理我在平台上出售的物品。

## 范围

- 每个已登录用户均可访问自己的商家界面，查看自己发布的商品列表
- 发布新商品：填写名称、价格、数量、描述、上传展示图
- 编辑已有商品：修改名称、价格、数量、描述、展示图
- 下架商品：将商品状态变更为"已下架"，已下架商品不在浏览页和详情页展示，但仍在商家界面可见，可重新上架
- 商家界面仅展示当前用户发布的商品

## 非目标

- 商品分类与搜索（后续独立 Spec）
- 商品款式/规格变体（已废弃）
- 后台审核流程（后续独立 Spec）
- 交易状态管理（后续独立 Spec）
- 商家主页对外展示（如其他用户查看商家信息）
- 删除商品（物理删除）

## 业务规则

- **BR-01**：仅已登录用户可访问商家界面；未登录用户请求返回 401。
- **BR-02**：发布商品时，名称、价格、数量、分类为必填项；描述和展示图为可选。
- **BR-03**：商品价格必须大于 0，数量必须为非负整数。
- **BR-04**：发布成功后的商品状态为"待审核"；审核通过后变为"在售"（见 013-后台审核）。
- **BR-05**：编辑商品时，仅可编辑当前用户自己发布的商品；不可编辑其他用户的商品。
- **BR-06**：下架商品将状态变更为"已下架"，已下架商品不在浏览页和详情页展示，但仍在商家界面可见，商家可重新上架。
- **BR-07**：商品展示图支持上传多张，第一张作为浏览页卡片封面图。
- **BR-08**：商品数量为 0 时进入"已售罄"状态（仍属"在售"）；已售罄状态持续满 7 天，系统自动将商品下架。若商家在 7 天内将数量增加至 ≥1，则退出已售罄状态，倒计时重置。

## Contract 影响

- 结论：新增
- 理由或影响摘要：新增商品发布、编辑、下架及商家商品列表接口，需认证。
- OpenAPI operation：
  - `POST /api/items`（`createItem`）— 发布商品
  - `PUT /api/items/{id}`（`updateItem`）— 编辑商品
  - `PATCH /api/items/{id}/status`（`updateItemStatus`）— 变更商品状态（下架）
  - `GET /api/items/mine`（`listMyItems`）— 查看自己发布的商品
- 迁移 / 废弃安排：不适用

## 验收标准

- **AC-01**：给定已登录用户和合法的商品信息，当请求 `POST /api/items` 时，返回 201 及创建的商品数据，商品状态为"待审核"。
- **AC-02**：给定未登录用户，当请求 `POST /api/items` 时，返回 401。
- **AC-03**：给定价格为 0 或负数，当请求发布商品时，返回 400 及错误提示。
- **AC-04**：给定商品拥有者，当请求 `PUT /api/items/{id}` 修改商品信息时，返回 200 及更新后的商品数据。
- **AC-05**：给定非商品拥有者，当请求 `PUT /api/items/{id}` 修改商品信息时，返回 403。
- **AC-06**：给定商品拥有者，当请求 `PATCH /api/items/{id}/status` 将状态变为"已下架"时，该商品不再出现在公开的 `GET /api/items` 中，但仍出现在 `GET /api/items/mine` 中且显示"已下架"状态。
- **AC-07**：给定已登录用户发布了多件商品，当请求 `GET /api/items/mine` 时，返回该用户的所有商品（含已下架），按发布时间倒序排列。
- **AC-08**：给定商品拥有者，当请求 `GET /api/items/mine` 时，已下架商品在列表中显示"已下架"状态标识。
- **AC-09**：给定发布商品时未填写 `category` 或填写了非法分类，当请求 `POST /api/items` 时，返回 400 及错误提示。
